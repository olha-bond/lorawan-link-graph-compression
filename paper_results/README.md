# Manuscript-facing results

This directory contains compact outputs used in the manuscript. It does not contain the original UVA parquet dataset.

## Figures

- `figures/coverage_vs_k.pdf` — manuscript Figure 2
- `figures/lambda_vs_worst_coverage.pdf` — manuscript Figure 3
- `figures/temporal_summary.pdf` — additional temporal diagnostic generated by the analysis code, not used as a main-text figure in the current manuscript

All three files are vector PDFs. The two external main-text result figures are `coverage_vs_k.pdf` and `lambda_vs_worst_coverage.pdf`. The algorithm box in the manuscript is typeset directly in LaTeX.

## Supplementary tables

- `supplementary/Table_S1_per_month_feasibility_and_link_budget.csv` contains per-month fit status, link budget, coverage, feasibility, and cold-start indicators for every evaluated policy, fitting method, and requirement
- `supplementary/Table_S2_oracle_budget_and_subset_similarity.csv` contains the budget difference from the same-month exact oracle and subset Jaccard similarity for every test-month record

## Synthetic scalability outputs

The `scalability/` subdirectory contains outputs from the synthetic scalability benchmark used for the manuscript scalability table:

- `31_empirical_link_coverage_profiles.csv` — empirical UVA per-link coverage fractions used to calibrate the synthetic generator
- `32_scalability_raw.csv` — per-seed benchmark results
- `32b_scalability_summary.csv` — aggregated values used for the manuscript scalability table
- `32c_scalability_calibration.csv` — target-versus-realised calibration summaries
- `32d_scalability_metadata.json` — benchmark settings and the scope note for the synthetic model

These files are regenerated with `scripts/run_scalability_experiment.py`. The scalability experiment is intentionally separate from `scripts/run_all.py`.

## Peer-review revision outputs

The `revision_1/` subdirectory contains additional analyses introduced during peer review of the revised manuscript:

- `33_boundary_month_sensitivity.csv` — robust all-month sensitivity after excluding the incomplete February 2024 and June 2025 records
- `34_heterogeneous_traffic_lambda_raw.csv` — per-run fairness-weight results under balanced and heterogeneous per-sensor traffic
- `34b_heterogeneous_traffic_lambda_summary.csv` — aggregated heterogeneous-traffic results reported in the revised manuscript
- `34c_heterogeneous_traffic_metadata.json` — experiment settings
- `34d_heterogeneous_multicover_raw.csv` — per-case comparison of the reusable ordering at `lambda = 1.0`, multi-cover greedy, and the exact reference under heterogeneous traffic
- `34e_heterogeneous_multicover_summary.csv` — aggregated multi-cover comparison across the 10-, 50-, and 100-sensor heterogeneous cases
- `35_fairness_worst_tie_diagnostic.csv` — diagnostic of the shared-minimum behaviour of the fairness-aware greedy
- `36_frozen_initial_window_sensitivity.csv` — summary of the frozen-policy sensitivity to the initial three-month fitting window
- `36b_frozen_initial_window_sensitivity_per_month.csv` — per-month results for the two frozen initial-window fits

The boundary-month experiment is regenerated with `scripts/run_revision_experiments.py`. The heterogeneous-traffic experiment and multi-cover comparison are regenerated with `scripts/run_revision_heterogeneity.py`, the tie diagnostic with `scripts/run_revision_fairness_diagnostic.py`, and the frozen-window sensitivity with `scripts/run_revision_frozen_sensitivity.py`.

## Provenance

The spatial and temporal files can be regenerated from the public UVA dataset by running `scripts/run_all.py` and then `scripts/export_publication_bundle.py --profile journal`.

The scalability files are regenerated separately with `scripts/run_scalability_experiment.py`.

The peer-review sensitivity outputs in `revision_1/` are regenerated with `scripts/run_revision_experiments.py`, `scripts/run_revision_heterogeneity.py`, `scripts/run_revision_fairness_diagnostic.py`, and `scripts/run_revision_frozen_sensitivity.py`.

The dataset manifest in `00_dataset_manifest.json` records the input validation and deployment dimensions used by the main pipeline.
